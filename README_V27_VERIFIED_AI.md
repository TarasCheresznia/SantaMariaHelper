# Santa Maria Helper V27 — проверка ответов по правилам

## Что исправлено

- Техническое поле `check` и служебное `OK` больше не показываются в интерфейсе.
- `/answer` возвращает `status`: `verified`, `clarification` или `insufficient_evidence`.
- Для подтверждённого ответа требуются конкретные пункты и дословные цитаты, сопоставленные с переданными текстами.
- Второй вызов Groq отдельно проверяет, что вывод и наказание подтверждаются этими пунктами, включая условия и исключения. Если проверка не пройдена, программа предлагает уточнение вместо категоричного ответа.
- Клиент не показывает ответы старого/несовместимого Worker как проверенные.
- Источники выводятся с URL. Данные биндера, профили, логотипы, 942 правила и 108 команд сохранены.

## Обязательно обновить Worker

1. Распакуйте ZIP. В Cloudflare → Workers & Pages → santa-maria-helper-api → Edit code.
2. Замените код на `cloudflare-worker/worker.js` и нажмите Deploy.
3. Убедитесь, что GET `/health` возвращает `"version":"27"` и `"evidence_verified":true`.
4. Затем соберите новое Windows-приложение с помощью `build_exe.bat` или GitHub Actions.
5. Проверьте размытый запрос «связь гос с краймом»: если неясны обстоятельства, приложение должно уточнить детали, а не придумывать запрет. Проверьте точное «Что такое DM и какое наказание по 5.7?» — должно ссылаться на правило при наличии прямого подтверждения.

Работа Groq и Windows UI в этой среде не проверялась. Два вызова Groq на проверенный ответ плюс один на интерпретацию увеличивают задержки и расход квоты. Вторая проверка модели снижает, но не исключает вероятность ошибок. Настройте rate limiting для публичного Worker. Секрет GROQ_API_KEY остаётся только в Cloudflare.
