# Santa Maria Helper V32 — исправление цепочки ответов

Главная проблема старых версий: отдельный `/interpret` увеличивал задержку, клиент выбирал мало правил и иногда заменял успешный ответ сообщением «Недостаточно данных». В V32 основной запрос выполняется **одним вызовом `/answer`**. В клиенте выбираются до 14 пунктов (вместо 9), а Worker возвращает ответ и ссылки только из переданных выдержек.

## Обязательно обновить обе стороны

1. Распаковать весь ZIP в **новую папку**.
2. В Cloudflare → Workers & Pages → `santa-maria-helper-api` → Edit code заменить ВЕСЬ код на `cloudflare-worker/worker.js` и нажать **Deploy**.
3. Открыть `https://santa-maria-helper-api.cernisenkotarik805.workers.dev/health` и проверить `"version":"32"`. Старый Worker не означает, что V32 ИИ подключена.
4. Запустить `build_exe.bat` на Windows с установленным Python. Запустить **новый** `dist/SantaMariaHelper.exe`.
5. В настройках нажать «Проверить сервер» — теперь видна версия Worker. Сначала проверить `Что такое DM?`, `Какое наказание за DM?`, `цвет одежды`, затем описать RP-ситуацию целым предложением.

Внимание: некоторые вопросы не имеют однозначного ответа без названия мероприятия. В этом случае программа должна уточнить контекст, а не выдумать запрет. Локальные 942 записи не являются гарантией полного охвата форума.

## Тестирование и ограничения

- В V32 проверены 16 Python-тестов проекта, 5 тестовых сценариев Worker с подставными ответами Groq, синтаксис JS/Python, база 942 записей и команды 108.
- **Не проверены** фактическая работа Groq с вашим секретом Cloudflare и запуск на Windows: среда сборки не Windows и в ней нет ключа Groq.
- Ответы нейросети всё ещё могут ошибаться; при реальных наказаниях необходимо сверять источники.
- Секрет `GROQ_API_KEY` оставлять только в Cloudflare. Публичный Worker без контроля доступа может исчерпать квоту Groq: перед массовой раздачей включить rate limiting/защиту злоупотреблений.
