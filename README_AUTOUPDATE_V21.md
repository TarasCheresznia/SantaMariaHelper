# Santa Maria Helper V21 — автообновление через GitHub Releases

## Начальная настройка (один раз)

1. Создайте GitHub-репозиторий и загрузите туда содержимое ЭТОЙ папки, включая `.github/workflows/build-windows.yml`.
2. В GitHub Settings → Actions → General → Workflow permissions выберите **Read and write permissions** (для публикации релизов).
3. Запустите сборку Windows через Actions → Build and publish Santa Maria Helper → Run workflow; скачайте EXE из Artifacts для первоначальной проверки.
4. В настройках Santa Maria Helper в поле GitHub укажите **ваш_логин/имя_репозитория**. Настройка сохраняется в `%LOCALAPPDATA%\SantaMariaHelper\config.json`.
5. Для выпуска обновления поменяйте `VERSION` в `app_updater.py` и сделайте git tag `v21.0.1` (или другой больший номер), затем push тега. GitHub Actions соберёт EXE и создаст Release с SHA-256.
6. При запуске приложение проверяет последний опубликованный Release, предлагает обновиться, загружает EXE, сверяет хеш, закрывается, заменяет EXE и запускает его снова.

**Важно**: старые версии V20 и ниже не имеют обновлятора; друзьям нужно вручную прислать EXE V21 один раз. Программа не обновляется, пока репозиторий не настроен и первый Release не опубликован. Работает с **публичными** GitHub Releases. Нужен интернет и права записи в папку EXE; не размещайте EXE в `Program Files`. Настройки и профили сохраняются в `%LOCALAPPDATA%`.

SHA-256 проверяет целостность скачанного файла, но не является криптографическим подтверждением личности издателя. Для более сильной защиты подпишите EXE сертификатом подписи кода и защищайте GitHub учётную запись двухфакторной аутентификацией. Автозамена на Windows требует дополнительной проверки в реальной системе.
